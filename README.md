# Принципы SOLID

**S - единственная ответственность**

Раньше один класс проверял заказ, считал суммы, печатал чек и сохранял данные. Теперь эти задачи разделены между отдельными классами

**O - открытость/закрытость**

Раньше новые скидки и способы оплаты добавлялись прямо в `processOrder()`. Теперь для этого добавляются стратегии и обновляются фабрики, а сам метод обработки не меняется

**L - подстановка Лисков**

Прямого нарушения в исходном коде не было. Теперь реализации можно подменять через общие интерфейсы, сохраняя их смысл: например, любая стратегия скидки возвращает скидку в деньгах

**I - разделение интерфейсов**

Перегруженных интерфейсов в исходном коде не было. Новые интерфейсы сделаны небольшими: каждый отвечает только за свою задачу

**D - инверсия зависимостей**

Раньше сервис сам занимался хранением и выводом данных. Теперь он получает зависимости через конструктор и работает через интерфейсы и абстрактные фабрики

# Описание работы

**Паттерны**

Strategy разделяет правила расчёта скидок и комиссий. Factory Method позволяет конкретным фабрикам создавать нужные стратегии через метод `createStrategy()`

**Поведение**

Расчёты, порядок проверок, сообщения об ошибках и формат чека сохранены. Тесты проверяют три варианта расчёта, ошибки валидации и вызовы сохранения


**Запуск проверок**

Запустить `main()` в классе `OrderServiceTest`. Если проверки пройдены, появится сообщение «Все проверки успешно пройдены»
